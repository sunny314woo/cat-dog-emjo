## 2. 怎样使用下面的列表

共13种风格，每种3条画风变体，合计39条。是为本项目起草的提示词，不是从平台复制的热门Prompt。

这些是互斥的**画风块**：选一条替换主模板中的 STYLE 槽位，再附原照片、身份模块、当前阶段版式与动作。不能同时把三个变体塞进同一格，也不要把三十九条整份发给模型。

共享要求：同一个指定人物或动物、保留核心身份、正确结构、主体完整、四周安全边距、无模型生成文字或水印、主体外透明或明确后处理抠图。预览阶段四格同姿势/表情；表情阶段按动作清单变化。全局负面词不能禁止3D，否则会抵消毛绒与黏土。

单张试样组合：
```text
根据原照片绘制同一个指定主体，保留其核心外观、年龄或物种结构。
[从下表选择一个完整画风变体]
本次姿势与构图：[具体共同姿势与head/half_body/full_body]
用户补充：[经过确认的动作、配饰或保留要求]
只画这个主体，轮廓完整，四周安全区域，无文字、水印或场景。
主体外透明；模型不支持时由程序抠图检查，不宣称提示词能保证alpha。
```

## 3. 参考图与补充提示词一起参与生成

目标合同：原照片负责身份，选中的单格预览负责画风，用户文字负责已确认的细节。它们共同参与同一次最终请求，不需要先把图片拼接成一张。

- 一张用户照片：最终请求发送主照片 + 所选风格图，共两张模型参考。
- 两张用户照片：最终请求发送主照片 + 同主体辅助照片 + 所选风格图，共三张模型参考。
- 两张用户照片不是两个主体；首版仍只生成一个指定人或动物。
- 预览阶段没有所选风格图，发送原照片、当前四种画风及用户补充。
- 图片顺序必须在文字里对应；只发送选中的单格，不发送四风格整张拼图。
- 补充“保留项圈/眼镜”“加小花”等进入配饰/服装模块；更换主体或画风需重新确认预览。用户事实纠正可以优先于自动识别，不默默改变身份。

火山接口支持图像与文本、多参考图共同输入。这里只确认能力可用于该设计，不保证三张图的身份与画风职责一定被正确遵循。[火山官方图像API](https://docs.volcengine.com/docs/ark/image-generation-api?lang=en)。实际请求还应使用匹配模型的尺寸、格式及参数。

当前官网是静态演示；豆包旧草稿请求未发送选中预览图，也没有商业服务端合并模块。这次改的是Prompt合同，功能还需实现和测试。

## 4. 收费点建议

现有 `docs/product/UPLOAD_PREVIEW_PAYMENT.md` 已描述一次完整免费体验、受保护预览、付费解锁的方向。本轮沿用该方向，不替换产品决定，也不冻结价格。

建议基础流程：上传 → 四风格 → 选风格 → 原图+风格图+用户文字生成高清九宫格（私有保存）→ 服务端输出逐格低清水印预览 → 满意后付款 → 解锁这份已有高清与裁切下载/ZIP/邮件。

- 第一次收费按钮放在结果预览旁，说明购买的是这一套的高清、透明裁切与交付。不要付款后重新画一套“高清版”，导致与预览不一致。
- 免费体验用完后的新主体、新照片或新风格，是新生成权益；在启动新任务前说明价格并付款。重新下载已购文件不再计一次新生成。
- 9张先验证；18/27可做数量套餐，生成成本与重试分别计入。暂不需要订阅或复杂积分。
- 免费预览不能把私有高清原图发到浏览器后只盖CSS水印；服务端只发送处理过的预览。

应现在确定收费节点、付费权益和系统失败处理，再用小规模原型验证出图和成本；不用等所有风格做好才想收费，也不用先做复杂会员系统。公开上线前打通支付确认、私有文件交付和失败恢复。
